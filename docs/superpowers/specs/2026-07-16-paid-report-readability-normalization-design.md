# 유료 리포트 가독성 구조화 명세

## 목표

9개 결과 유형의 유료 리포트를 모바일에서 빠르게 이해하고 계속 읽을 수 있게 만든다. 원본의 의미와 12개 섹션 순서는 보존하며, 붙은 문장·긴 텍스트 덩어리·평면적인 항목 나열을 읽는 단위로 정리한다.

## 범위

- 대상: `src/content/resultCopy/paidReports/`의 9개 리포트 데이터
- 문장 끝과 다음 문장이 붙은 지점을 분리한다.
- 이미 있는 제목·표·목록·강조 항목을 의미에 맞는 블록으로 재배치한다.
- `문제 → 손실 → 해법`, `첫 수익 → 반복 수익 → 고수익`, `3일 → 5일 → 1주`의 순서를 화면에서 분명히 보이게 한다.
- 기존 리포트 맵, 카드 확장, 다음 분석, 모바일 표 표현, 색상·폰트 방향을 유지한다.

## 제외 범위

- 유료 리포트의 주장·조언·예시·표 내용 추가 또는 삭제
- 결과 유형 산정, 점수, 무료 결과, 결제·잠금·로그 변경
- 12개 섹션 순서 변경
- 새로운 시각 스타일 또는 애니메이션 추가

## 콘텐츠 구조 규칙

### 핵심 판정

- `한 줄 정리`는 독립된 강조 블록으로 유지한다.
- 뒤따르는 설명은 한 문단에 2~3문장 이하가 되게 나눈다.

### 맞춤 해석 키워드와 실행 요약

- `재물 흐름`, `강한 축`, `막히는 축`, `보조 해석`, `추천 수익화`, `주의할 패턴`은 각각 독립된 강조 블록으로 유지한다.
- `첫 목표`, `첫 판매`, `첫 기준`, `성장 방향`, `가장 먼저 할 일`, `주의할 점`도 같은 방식으로 유지한다.
- 라벨과 본문이 붙은 원본은 라벨 뒤에 줄바꿈을 둔다.

### 수익 확장과 막히는 지점

- `첫 수익 만들기`, `반복 수익 만들기`, `고수익으로 키우기`는 각각 별도 강조 블록으로 만든다. 해당 설명은 2~3문장 단위로 분리한다.
- 각 `문제 N`은 제목 라벨을 유지하고, 본문을 아래 순서의 한 강조 블록으로 둔다.

```text
문제
원본의 문제 설명

손실
원본의 손실 설명

해법
원본의 해법 설명
```

- 기존 리포트 읽기 UI의 단계 표현을 사용해 문제·손실·해법이 시각적으로 분리되게 한다.

### 이번 주 맞춤 플랜

- `3일 실천`, `5일 점검`, `1주 실험`은 각각 독립된 강조 블록으로 만든다.
- 행동 항목은 `list` 블록으로 표현한다.
- 도입 문장과 마무리 문장은 짧은 문단으로 분리한다.

## 데이터와 렌더링

- 기존 `PaidReportBlock` 타입(`paragraph`, `highlight`, `list`, `table`)만 사용한다.
- 새 런타임 문장 분해 로직은 추가하지 않는다. 모든 분리는 정적 리포트 데이터에 명시한다.
- 기존 `highlightStages`가 `문제`, `손실`, `해법`을 단계형 콘텐츠로 표시하는 동작을 유지한다.
- `list`는 실행 항목에만 사용하며, 원본의 문장 순서를 유지한다.

## 검증

- 9개 파일에 붙은 문장 패턴(`문장부호` 뒤 한글)이 남아 있지 않은지 검사한다.
- 모든 리포트가 12개 섹션을 유지하는지 검사한다.
- 9개 리포트의 `문제 N` 섹션이 문제·손실·해법 단계형 블록을 포함하는지 검사한다.
- 9개 리포트의 12번째 섹션이 3일·5일·1주 행동 단위를 포함하는지 검사한다.
- 수정 파일 ESLint, UI 계약 테스트, `npm run build`, 390px 리포트 확장 화면을 확인한다.

## 결정

문장 자동 분해가 아니라 정적 리포트 데이터의 의미 단위 구조화를 선택한다. 유료 콘텐츠에서 문맥이 잘못 잘리는 위험을 없애고, 원본의 의미를 보존하면서도 읽는 흐름을 통제하기 위해서다.
