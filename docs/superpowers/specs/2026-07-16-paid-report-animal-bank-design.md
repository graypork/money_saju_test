# 결과 유형별 유료 리포트 연결 명세

## 목표

현재 상세 리포트는 어떤 테스트 결과에서도 백조형 샘플을 표시한다. 결과 계산으로 이미 생성되는 9개 `animalKey`에 맞춰, 각 유형의 실제 유료 리포트를 한 번에 연결한다.

## 범위

- 대상 유형: `fox`, `ox`, `squirrel`, `hawk`, `tiger`, `rabbit`, `deer`, `swan`, `otter`
- 원본: `docs/paid-reports-source/`의 9개 유료 리포트 문서
- 결과 화면에서 전달한 쿼리 파라미터, 결과 계산, 점수, 동물 선택, 결제·잠금·로그 동작은 그대로 둔다.
- 리포트 문장, 표의 내용, 섹션 순서는 원본을 기준으로 보존한다.

## 제외 범위

- 새 리포트 문구 작성 또는 기존 문구의 의미 변경
- 결제·잠금 플로우 구현 또는 변경
- 무료 결과 페이지 구성 변경
- 결과 유형 산정 규칙 변경

## 데이터 구조

1. 기존 `PaidReport`, `PaidReportSection`, `PaidReportBlock` 타입을 유지한다.
2. 새 리포트 뱅크는 `animalKey`를 키로 하며, 9개 `PaidReport`를 명시적으로 보관한다.
3. 각 원본의 구조를 다음 블록으로 옮긴다.
   - 본문 문단 → `paragraph`
   - 항목명과 내용의 쌍 → `highlight`
   - 순서 없는 실행 항목 → `list`
   - 표 → `table`
4. 원본에서 제목 표기가 불규칙한 문서는 의미를 해석해 같은 블록 구조로 정규화하되, 문장 자체와 원래 섹션 순서는 수정하지 않는다.

## 리포트 선택 흐름

```text
URL 쿼리
  → calculateWealthResult
  → buildResultCopy(result).animalKey
  → paidReportByAnimalKey[animalKey]
  → PaidReportView
```

- `buildResultCopy`가 돌려준 `animalKey`만 선택에 사용한다.
- 정상 결과의 9개 키는 모두 리포트 뱅크에 존재해야 한다.
- 예상 밖의 키이거나 해당 데이터가 없으면 다른 유형의 리포트로 대체하지 않는다. 리포트를 표시할 수 없다는 안내와 무료 결과로 돌아가는 동작을 제공한다.

## 화면과 상호작용

- 기존 `PaidReportView`의 리포트 맵, 확장 읽기 모드, 다음 분석 버튼, 읽기 가독성 규칙을 모든 유형에 그대로 적용한다.
- 사용자가 무료 결과에서 상세 리포트로 이동하면, 방금 본 결과 유형과 동일한 동물명·섹션의 리포트가 보여야 한다.
- 리포트에서 무료 결과로 돌아갈 때 기존 쿼리 파라미터를 보존한다.

## 검증

- 9개 키가 각각 리포트 뱅크에 존재하는 자동 검증을 추가한다.
- 백조형 샘플을 고정으로 전달하는 코드가 제거됐는지 확인한다.
- 유효한 리포트 URL에서 결과의 `animalKey`와 렌더링한 리포트의 `animalKey`가 일치하는지 확인한다.
- 수정 파일의 ESLint, UI 테스트, `npm run build`를 실행한다.
- 390px 환경에서 무료 결과 → 상세 리포트 → 무료 결과 흐름을 한 번 검증한다.

## 결정

9개 원본을 런타임 Markdown 파싱 없이 타입이 검증되는 리포트 뱅크로 전환한다. 원본 서식의 불균일성으로 인한 화면 예외를 피하고, 각 유형의 실제 문구와 순서를 안정적으로 보존하기 위해서다.
